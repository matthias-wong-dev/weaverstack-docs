This addendum corrects the interpretation of the original `findings.md` and `results.md`. It does not replace or edit those files, and it does not turn locally checked corrections into live Fabric passes. The original command transcript and diagnostic material remain part of the evidence record.

## Status vocabulary

| Status | Meaning |
| --- | --- |
| PASS | The stated journey and its material outcome were observed. |
| FAIL | The documented or product path was executed and did not produce its required outcome. |
| DOC ISSUE | The product behaviour was consistent with its contract, but the instructions were incomplete, unsafe or inaccurate. |
| ENVIRONMENT ISSUE | Tenant, permission, publication or pre-release conditions prevented a product conclusion. |
| NOT TESTED | The path was not executed. |
| INCONCLUSIVE | The observation did not distinguish the competing explanations or prove the stated diagnosis. |

A corrected fixture or clean `weaver check` is not a live PASS. A failed original attempt remains in the history after a corrected rerun passes.

## Corrections to the original findings

### Build pruning and the Folder tutorial — DOC ISSUE

Build intentionally reconciles selected Weaver-managed physical items and may prune undeclared co-located content. The original tutorial put manually supplied source files inside the selected destination Lakehouse, so the tutorial crossed the ownership boundary it meant to teach.

The corrected example keeps `ParcelSourceArchive` in a separate unselected Lakehouse and reaches it through a physical Folder Shortcut. The earlier pruning observation remains useful evidence of the unsafe layout, but it is not classified as a product data-loss defect.

### Warehouse bookmark and custom-delete example — DOC ISSUE / NOT TESTED

The original page showed a transformation over `Source.Parcel` without source provisioning or a runnable checked fixture. The corrected fixture now supplies a separate `ParcelSource` Warehouse, source setup/seed/change scripts, a physical Warehouse Shortcut and the two-result incremental Table.

The current checker requires `Dependencies: []` because T-SQL inference does not resolve the physical Shortcut View. That override is documented as a current limitation rather than presented as the normal inference path. The live Warehouse journey has not yet been rerun.

### Fabric notebook-source `.py` input — DOC ISSUE

The original reference described `.py` too broadly. Fabric expects its notebook-source export format, including the `# Fabric notebook source` prologue, cell markers and metadata blocks. The corrected reference includes a complete checked fixture and keeps `.ipynb` as a supported alternative.

A successful notebook-definition push transports the Notebook definition only. It does not transport a Weaver project held in Notebook Resources.

### Mirror destination provisioning — DOC ISSUE

Mirror reconstructs contents inside existing destination items; it does not provision the destination catalogue Warehouse or selected Lakehouses and Warehouses. The corrected development-cycle page now includes those prerequisites, a concrete portal setup route and one review-and-confirm invocation.

### Initialise, Workflow and Windows output — DOC ISSUE

The fully specified Initialise command runs directly rather than opening the wizard. A real terminal can confirm an interactive Workflow; unattended execution requires explicit authorisation with `--yes --non-interactive`, and piping `y` is not equivalent to terminal confirmation.

Current Weaver configures CLI streams as UTF-8. Capturing programs must decode output as UTF-8. `PYTHONUTF8=1` is retained only as a per-process compatibility workaround for an older launcher or wrapper that fails before Weaver configures its streams.

### Environment publication during the pre-PyPI run — FAIL with ENVIRONMENT ISSUE context

The released publication path reported no update for an Environment whose libraries were not published, and the later Python Load failed. That remains a product finding for the companion product ticket. The unavailable current package on PyPI was a separate pre-release environment condition; it does not convert false publication state into a documentation convention.

The documentation keeps normal released-package publication as the public path. `--dev` is described only for an editable source checkout used to test an unreleased build.

### Health item filtering — FAIL

The original run showed unselected items in Health activity while summary counts were scoped. That remains a product finding for the companion ticket; the documentation does not redefine the output as intentionally global.

### Piped Session output — INCONCLUSIVE

The merged non-TTY transcript showed repeated progress blocks, but row state did not demonstrate duplicate mutation. The evidence does not establish that commands executed twice. Preserve the transcript for product investigation without classifying double execution as proven.

### Mirror and Wipe confirmation order — INCONCLUSIVE

Merged output from non-interactive runs showed the settled-plan text after progress output. It did not exercise a real terminal confirmation, so it does not prove that mutation preceded confirmation. The real-TTY decline and confirmation paths remain to be tested.

### Bundle-only mutation — INCONCLUSIVE

The original sequence established that a later install failed with an already-existing object, but it did not isolate which operation created the object. A later clean bundle-only attempt did not reproduce the mutation. Do not classify bundle-only mutation as established without a controlled before/after reproduction.

### Stability refusal — INCONCLUSIVE

Directly mutating target rows and observing them remain changed did not prove that Weaver refused a proposed source-to-target update. The decisive test must change source rows after a baseline Load, leave declarations and target data otherwise untouched, exceed a known active threshold, and verify the refusal, unchanged target and bookmark before testing recovery below the limit.

### Notebook and installed-interface coverage — NOT TESTED or limited evidence

The original notebook job and physical state supported part of the in-Fabric Load path. They did not establish all of the following:

- Build from a project in Notebook Resources;
- notebook Build followed by desktop Load and Test;
- desktop Build followed by notebook Load and Test;
- direct imports and calls for the installed Folder, Python Table, generated Spark SQL Table and validation; or
- a complete Fabric Git round trip for built-in Resources.

Top-level `weaver.load()` inside Fabric is not independent evidence for direct installed-object calls. Notebook Load, Test and Health outcomes must be separated according to the reports and physical evidence actually captured.

## Black-box continuation handover

Use the final pull-request head, record its exact commit, and record the installed Weaver package version and Fabric runtime for each run. If the package changes, segment the evidence and rerun affected paths.

The continuation tester must use public documentation, checked examples, public interfaces and observed Fabric state. It must not inspect Weaver implementation source, internal design notes or product tests to repair an instruction.

Run only the remaining focused paths:

1. both corrected incremental journeys, including repeated Build, source survival, update/delete, no-change Load and bookmark inspection;
2. notebook-first Build from Resources and both notebook/desktop reverse routes;
3. direct installed Folder, Python Table, generated Spark SQL Table and validation calls;
4. a controlled stability refusal and recovery, plus independent fail-fast, fault-tolerant and tolerated-reject branches; and
5. Wipe `--unbind` and real-terminal decline/confirm checks in disposable destinations.

Keep raw commands, exit codes, stdout, stderr, notebook cells, returned reports, timestamps and authored test projects. Record unsupported setup or permissions as `ENVIRONMENT ISSUE` or `NOT TESTED`; do not replace an unavailable path with a different test and call it a pass.
