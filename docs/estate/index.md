# Coordinate your estate

Two working items already raise shared questions: which runs first, where does the same source deploy, and what happened after the last change? Weaver keeps those relationships and results together.

[Connect items](connected-items.md), [map development and production workspaces](environments.md), then [read Catalogue and Health](catalogue-and-health.md). The [Catalogue Dashboard](catalogue-dashboard.md) shows the same catalogue in Power BI.

Use [the development cycle](development-cycle.md) for ordinary edits and [run, test and inspect](operate.md) for the installed estate. [Recover failed work](recovery.md) by choosing the smallest action its state needs; [Mirror](mirror.md) is an optional development baseline, not the first step.

When you need finer control, [select part of the estate](selective-runs.md), [limit concurrency](concurrency.md) and [investigate performance](performance.md). [Workflows and controlled deployment](automation-and-deployment.md) takes that working loop into automation.
