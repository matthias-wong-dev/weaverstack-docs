# A first Lakehouse pipeline with Python

Turn a carrier CSV export into a Delta Table using ordinary Python. Weaver manages the files and Table, discovers the dependency from your import and records each Load's result.

## Create the project

[Install the documented Weaver snapshot](../getting-started/installation.md). Use a disposable Fabric workspace on running capacity where you can create or modify a catalogue Warehouse, Lakehouse and Environment. Replace `Parcel Development` with that workspace:

```bash
weaver initialise \
  --workspace "Parcel Development" \
  --project-folder ./parcel-lakehouse-python \
  --catalogue Catalogue \
  --environment Weaver \
  --lakehouse Landing \
  --no-example
cd parcel-lakehouse-python
```

Initialise writes `workspace-config.yml`, an empty `Lakehouse/Landing` directory and `Environment/Weaver.Environment`. Keep this project for the following Spark SQL and validation pages. The [checked document snapshot](https://github.com/matthias-wong-dev/weaverstack-docs/tree/main/examples/parcel-lakehouse) has the source files and a checkpoint list; the two files below are the first checkpoint.

## Stage the carrier export

Create `Lakehouse/Landing/Files/Parcel__Events.py`:

```python
"""
Folder ID: Parcel.Events

Description: Parcel tracking events as CSV files.

Lineage: A deterministic carrier export generated by this example.

File key: "*.csv"

Incremental: false
"""

from weaver import Folder


EVENTS = """Parcel ID,Event sequence,Status,Depot
P-1001,1,Accepted,North
P-1001,2,In transit,Central
P-1002,1,Delivered,South
"""


class Parcel__Events(Folder):
    def read(self):
        with self.staging_folder() as staging:
            (staging.path / "events.csv").write_text(EVENTS, encoding="utf-8")
        return staging
```

This small export is generated so the first run needs no external carrier system. `read()` returns the staging Folder issued by Weaver. `Incremental: false` makes the staged files a complete snapshot; Folders otherwise default to incremental loading.

## Read it into a Table

Create `Lakehouse/Landing/Tables/Parcel__Event.py`:

```python
"""
Table ID: Parcel.Event

Description: One row per parcel tracking event.

Lineage: The parcel event CSV snapshot managed in this Lakehouse.

Primary key: Parcel ID, Event sequence

Schema:
  Parcel ID: string
  Event sequence: integer
  Status: string
  Depot: string
"""

from Files.Parcel__Events import Parcel__Events
from weaver import Table


class Parcel__Event(Table):
    def read(self):
        source = Parcel__Events(self).spark_path()
        return (
            self.spark.read.option("header", True)
            .csv(source)
            .selectExpr(
                "`Parcel ID`",
                "cast(`Event sequence` as int) as `Event sequence`",
                "Status",
                "Depot",
            )
        )
```

The `Files.Parcel__Events` import establishes the dependency. The Table reads the managed Folder through `spark_path()` and casts the event sequence for the declared schema. `Lineage` is descriptive; it does not order execution.

## Check, build and load

```bash
weaver check
```

Check should print `Project valid.` It validates the local declarations and dependency; it does not execute `read()` or deploy the project.

Before the first remote Build, publish the generated Environment:

```bash
weaver fabric environment publish --path Environment/Weaver.Environment
```

Publication installs the Weaver release used by your local client into the Fabric Environment. The [runtime page](runtime.md) explains version matching and when to republish. Spark-backed Build checks its hosted runtime before mutation even though it does not call your `read()`.

Then, from this project directory:

```bash
weaver build --item Lakehouse/Landing
weaver load Lakehouse/Landing
weaver health --item Lakehouse/Landing
```

Build should install both definitions without failed actions. Item-wide Load should run `Files/Parcel.Events` before `Tables/Parcel.Event`: one CSV file, then three rows. Health should show Green Build and Load sections.

## Inspect the Table

Query the Landing Lakehouse SQL analytics endpoint once the Table is visible there:

```sql
select [Parcel ID], [Event sequence], [Status], [Depot]
from [Parcel].[Event]
order by [Parcel ID], [Event sequence];
```

The result should contain the three rows in `EVENTS`. The managed file is `Files/Parcel/Events/events.csv`.

You now have the event history in a Table. [Add a Spark SQL CurrentStatus Table](spark-sql.md) to answer the next question: where is each parcel now? Keep the Python Event and its Folder; the next page adds one transformation to this project.

For edits to either declaration, Check and Build again, then use `weaver load Lakehouse/Landing --stale` for post-Build catch-up. Changing the `EVENTS` constant is a code change, not an external data-only incremental run. [Loading changes](incremental.md) supplies that later variation. Exact authored forms are in [Folder](../reference/weaver-documents/folder.md) and [Table](../reference/weaver-documents/table.md).
