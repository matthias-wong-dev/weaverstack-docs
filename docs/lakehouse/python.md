# A first Lakehouse pipeline with Python

Turn a carrier CSV export into a Delta Table using ordinary Python. Weaver manages the files and Table, discovers the dependency from your import and records each Load's result.

## Create the project

You need [Weaver installed](../getting-started/installation.md) and a disposable Fabric workspace on running capacity where you can create Warehouses, Lakehouses and Environments. The example uses `Parcel Development`; substitute your own.

=== "New project"

    ```bash
    weaver initialise \
      --workspace "Parcel Development" \
      --project-folder ./parcel \
      --catalogue Catalogue \
      --environment Weaver \
      --lakehouse Landing \
      --example Parcel
    cd parcel
    ```

    In the Terminal, press Enter to skip the optional Warehouse, choose `1` to continue, and answer `n` to publishing the Environment; the next section publishes it.

=== "Add to the Warehouse project"

    If you already have the `parcel` project from the [Warehouse task](../warehouse/first-project.md), add Landing to it. From inside `parcel`:

    The Terminal wizard reads the existing bindings, so it only asks you to confirm. Choose `1`, then answer `n` to publishing the Environment.

    Your Warehouse files stay as they were. Initialise also adds a separately named Warehouse Table that reads Landing; [Connect items and dependencies](../estate/connected-items.md) uses it later.

    ```bash
    weaver initialise --workspace "Parcel Development" --project-folder . --lakehouse Landing --example Parcel
    ```

## Inspect the carrier export {#stage-the-carrier-export}

Open `Lakehouse/Landing/Files/Parcel__Events.py`:

<!-- initialise:Lakehouse/Landing/Files/Parcel__Events.py -->
```python
"""
Folder ID: Parcel.Events

Description: Parcel tracking events as CSV files.

Lineage: A deterministic carrier export generated by this example.

File key: "*.csv"

Incremental: false
"""

from weaver import Folder

EVENTS = """Parcel ID,Event sequence,Status,Depot
P-1001,1,Accepted,North
P-1001,2,In transit,Central
P-1002,1,Delivered,South
"""


class Parcel__Events(Folder):
    def read(self):
        with self.staging_folder() as staging:
            (staging.path / "events.csv").write_text(EVENTS, encoding="utf-8")
        return staging
```
<!-- /initialise -->

The small CSV gives this first run three known events without an external carrier connection. The Folder stages those bytes; `Incremental: false` declares the complete set of files.

## Inspect the Python Table {#read-it-into-a-table}

Open `Lakehouse/Landing/Tables/Parcel__Event.py`:

<!-- initialise:Lakehouse/Landing/Tables/Parcel__Event.py -->
```python
"""
Table ID: Parcel.Event

Description: One row per parcel tracking event.

Lineage: The parcel event CSV snapshot managed in this Lakehouse.

Primary key: Parcel ID, Event sequence

Schema:
  Parcel ID: string
  Event sequence: integer
  Status: string
  Depot: string
"""

from Files.Parcel__Events import Parcel__Events

from weaver import Table


class Parcel__Event(Table):
    def read(self):
        source = Parcel__Events(self).spark_path()
        return (
            self.spark.read.option("header", True)
            .csv(source)
            .selectExpr(
                "`Parcel ID`",
                "cast(`Event sequence` as int) as `Event sequence`",
                "Status",
                "Depot",
            )
        )
```
<!-- /initialise -->

The Table reads the upstream Folder and casts Event sequence to the declared integer type.

The Folder and Table run in Fabric Spark, so publish the generated Environment once before the first Build. It adds your installed Weaver version to the Environment's libraries:

```bash
weaver fabric environment publish --path Environment/Weaver.Environment
```

Fabric takes about five to seven minutes to publish an Environment. You only repeat this when you upgrade Weaver or change the Environment's libraries; [Running Python in Fabric](runtime.md) has the details.

## Inspect the Table

In the Fabric portal, open the Landing **SQL analytics endpoint** and query the Table:

```sql
select [Parcel ID], [Event sequence], [Status], [Depot]
from [Parcel].[Event]
order by [Parcel ID], [Event sequence];
```

The result should contain the three rows in `EVENTS`. The managed file is `Files/Parcel/Events/events.csv`.

## What Weaver handled

The Folder staged the file, and Weaver published it under `Files/Parcel/Events`. The Python import supplied the Folder → Table dependency, so Load ran the file work first. Build installed the Table and its code; Load applied the three rows and recorded the result. `Lineage` remains a description, not another dependency declaration.

You now have the event history in a Table. [Inspect the Spark SQL CurrentStatus Table](spark-sql.md) to answer the next question: where is each parcel now? Keep the Python Event and its Folder; the next page explains the generated transformation in this same project.

For edits to either declaration, Check and Build again, then use `weaver load Lakehouse/Landing --stale` for post-Build catch-up. Changing the `EVENTS` constant is a code change, not an external data-only incremental run. [Loading changes](incremental.md) supplies that later variation. Exact authored forms are in [Folder](../reference/weaver-documents/folder.md) and [Table](../reference/weaver-documents/table.md).
